Customer Relationship Management (CRM)

Overview

The webERP CRM module provides lead management and opportunity pipeline functionality for tracking potential customers from initial contact through to conversion, and managing sales opportunities from prospect through to close. The system allows sales teams to capture lead information, track lead status through a defined workflow, convert qualified leads into webERP customer accounts, and manage a visual sales pipeline with probability-weighted forecasting.

The CRM module consists of the following scripts:

  • CRMLeads.php — Browse and search all leads
  • CRMLeadEntry.php — Create and edit lead records
  • CRMLeadInquiry.php — View lead details (read-only)
  • CRMLeadConvert.php — Convert a lead into a customer
  • CRMSelectLead.php — Popup lead selector
  • CRMLeadSources.php — Maintain lead source reference data
  • CRMActivityTypes.php — Maintain activity type reference data
  • CRMPipelineStages.php — Maintain pipeline stages
  • CRMOpportunities.php — Browse and search opportunities
  • CRMOpportunityEntry.php — Create and edit opportunities
  • CRMOpportunityInquiry.php — View opportunity details (read-only)
  • CRMPipeline.php — Visual pipeline board
  • CRMForecast.php — Sales forecast report
  • CRMActivities.php — Browse and search all CRM activities
  • CRMActivityEntry.php — Create and edit activities
  • CRMCalendar.php — Monthly calendar view of scheduled activities
  • CRMMyActivities.php — Personal activity dashboard

Lead Status Workflow

Each lead follows a status workflow that tracks its progression from initial capture to conversion. The available statuses are:

New
The lead has been captured but no contact has been made yet. This is the default status for newly created leads.
Contacted
Initial contact has been made with the lead. This indicates that a sales person has reached out by phone, email, or meeting.
Qualified
The lead has been assessed and determined to be a genuine prospect with a real opportunity for business.
Unqualified
The lead has been assessed and determined not to be a viable prospect at this time.
Converted
The lead has been converted into a full webERP customer account. Once converted, the lead record is retained for historical reference and links to the new customer record. Converted leads cannot be deleted.

Browsing and Searching Leads

The lead list (CRMLeads.php) is the main entry point for lead management. It displays all leads in a table showing key information at a glance.

Search and Filter

The search form at the top of the page provides the following filters to narrow the list of leads:

Keywords
Searches across the lead's first name, last name, and company name. Partial matches are supported.
Status
Filter leads by their current workflow status (New, Contacted, Qualified, Unqualified, or Converted), or select All to see every status.
Assigned To
Filter by the salesperson assigned to the lead. The dropdown is populated from the salesman table.
Source
Filter by the lead source (e.g. Website, Referral, Trade Show). Only active sources appear in this list.

Filter selections are remembered in the session, so they persist when navigating away and returning to the lead list.

Lead List Columns

The results table displays:

  • First Name and Last Name
  • Company
  • Status (the current workflow stage)
  • Assigned To (the salesperson)
  • Estimated Value (with currency)
  • Source (how the lead was acquired)
  • Created date

Each row provides links to Edit the lead, View its full details, and (if not yet converted) Convert it to a customer.

Creating and Editing Leads

New leads are created via CRMLeadEntry.php. A link to add a new lead is provided at the top of the leads list. The same script is used to edit existing leads when accessed with a LeadId parameter.

Lead Fields

First Name / Last Name
The contact person's name. At least one of these must be entered.
Company
The organisation name, if applicable.
Job Title
The contact person's role within their organisation.
Email
Contact email address. If entered, it is validated for correct format.
Phone / Mobile
Contact telephone numbers.
Website
The company or lead's website URL.
Industry
The industry sector the lead operates in.
Source
How the lead was acquired. Selected from the list maintained in CRMLeadSources.php.
Status
The current workflow status of the lead (see Lead Status Workflow).
Assigned To
The salesperson responsible for this lead. Selected from the salesman table.
Estimated Value
The estimated monetary value of the opportunity.
Currency
The currency for the estimated value. Selected from the currencies configured in the system.
Notes
Free-text area for any additional information about the lead.

Deleting Leads

Leads can be deleted from the edit page, provided they have not been converted to a customer. Once a lead has been converted its status is set to "converted" and deletion is prevented to preserve the audit trail.

Viewing Lead Details

CRMLeadInquiry.php provides a read-only view of all information held against a lead. It displays all the fields described above together with audit information:

  • Created date and the user who created the record
  • Last updated date and the user who last modified it
  • If converted: the customer code the lead was converted to and the conversion date, with a link to the customer record

From the inquiry page there are links to edit the lead, convert it to a customer (if not yet converted), or return to the leads list.

Converting a Lead to a Customer

CRMLeadConvert.php converts a qualified lead into a full webERP customer account (debtorsmaster record). This is typically done once the lead has progressed through the workflow and is ready to become a trading customer.

Conversion Process

When converting a lead the system:

  1. Displays a summary of the lead's details for review
  2. Presents a form to capture the additional fields required for a customer record that are not part of the lead data
  3. On submission, creates a new debtorsmaster record using data from the lead combined with the additional fields entered
  4. Updates the lead record: sets the status to "converted", records the new customer code in the convertedto field, and timestamps the conversion

Additional Fields for Conversion

The conversion form requires:

Customer Number
If the system is not configured for automatic debtor numbering, a customer code must be entered manually. The system checks that it does not already exist.
Currency
Pre-filled from the lead's currency, but can be changed.
Payment Terms
The payment terms to apply to the new customer account.
Sales Type
The price list / sales type for the customer.
Customer Type
The debtor type classification.

The customer name is derived from the lead's company name if one was entered, otherwise from the lead's first and last name. If a lead has already been converted, the script displays a message with a link to the existing customer record.

Lead Source Maintenance

CRMLeadSources.php maintains the reference list of lead sources. Lead sources describe how leads are acquired (e.g. Website, Referral, Trade Show, Cold Call). This data is used when creating leads and for filtering the lead list.

Lead Source Fields

Source Name
A descriptive name for the lead source, up to 40 characters.
Active
Controls whether the source appears in selection lists. Inactive sources are hidden from the lead entry form but are retained for reporting on existing leads. The active flag is only shown when editing an existing source.

A lead source cannot be deleted if any leads are assigned to it. In this case, deactivate the source instead to hide it from future use.

The system is seeded with a default set of sources: Website, Referral, Trade Show, Cold Call, Advertisement, Social Media, Partner, and Other.

Activity Type Maintenance

CRMActivityTypes.php maintains the reference list of activity types that can be logged against leads. Activity types categorise the interactions and tasks associated with lead management.

Activity Type Fields

Type Code
A short code identifying the activity type, up to 20 characters (e.g. "call", "email", "meeting"). The code cannot be changed once created.
Type Name
A descriptive name for display, up to 40 characters.
Active
Controls whether this activity type is available for selection. Inactive types are hidden from new entries but retained for historical records.

An activity type cannot be deleted if it is referenced by existing activity records. Deactivate it instead to prevent future use.

The system is seeded with the following default activity types: Note, Phone Call, Email, Meeting, Task, and Demo.

Opportunity Pipeline

The opportunity pipeline extends the CRM module with deal tracking from prospect through to close. Opportunities can be linked to a customer, a lead, or both (e.g. after lead conversion). The pipeline provides visual management of the sales funnel, probability-weighted forecasting, and stage-by-stage progress tracking.

Pipeline Stage Maintenance

CRMPipelineStages.php maintains the configurable pipeline stages that opportunities move through. Each stage defines a default probability, a display sequence, and whether the stage represents a closed outcome.

Stage Name
A descriptive name for the stage, up to 40 characters.
Probability %
The default win probability when an opportunity enters this stage. For closed-won stages this is forced to 100; for closed-lost, 0.
Sequence
Determines the left-to-right display order of stages on the pipeline board.
Closed Stage
If checked, the stage represents a final outcome. The closed outcome must be set to either "won" or "lost".
Active
Controls whether the stage appears in selection lists. A stage cannot be deactivated while it has open opportunities assigned.

A stage cannot be deleted if any opportunities are assigned to it. The system is seeded with default stages: Prospecting, Qualification, Needs Analysis, Value Proposition, Proposal/Quote, Negotiation, Closed Won, and Closed Lost.

Managing Opportunities

CRMOpportunities.php is the main list view for browsing and filtering opportunities. Filters include keywords, pipeline stage, assigned salesperson, and outcome (open, won, or lost). Filter selections are remembered in the session. The list shows each opportunity's name, customer or lead, stage, amount, weighted value, expected close date, and outcome.

CRMOpportunityEntry.php is used to create and edit opportunities.

Opportunity Name
A short description of the deal.
Customer / Lead
At least one of these must be specified. A customer is selected from the debtors master, a lead from the CRM leads table. Both can be set simultaneously (e.g. after a lead has been converted).
Pipeline Stage
The current stage. Changing the stage automatically updates the probability to the stage's default value. Selecting a closed stage forces the probability and sets the outcome and closed-at date.
Probability
The estimated win probability (0–100%). Auto-filled from the stage but can be manually adjusted for open stages.
Amount / Currency
The deal value and its currency.
Expected Close
The date the deal is expected to close.
Assigned To
The salesperson responsible for the opportunity.
Description
Detailed notes about the opportunity.

When an opportunity is moved to a closed-won stage the outcome is set to "won" and the probability is forced to 100%. For closed-lost the outcome is "lost" and probability is 0%. Moving an opportunity back to an open stage reverts the outcome to "open" and clears the closed-at date. Only open opportunities can be deleted.

CRMOpportunityInquiry.php provides a read-only view of all opportunity details including audit information (created by, updated by) and any linked sales orders.

⬆ Top

Pipeline Board

CRMPipeline.php displays a visual pipeline board showing all active stages as columns with opportunity cards arranged within each column. Each card shows the opportunity name, customer or lead name, amount, and expected close date. Stage totals and a grand total are displayed at the bottom, grouped by currency.

An optional salesperson filter narrows the view to a single salesperson's pipeline. Stages that have been deactivated are still shown if they contain open opportunities, ensuring no deals are hidden.

Forecast Report

CRMForecast.php provides three forecast views of open opportunities, all using probability-weighted values grouped by currency:

By Salesperson
Total pipeline value and weighted value per salesperson.
By Expected Close Month
Deals grouped by the month they are expected to close, showing count, total value, and weighted value.
By Pipeline Stage
Deals grouped by their current stage, showing count, total value, weighted value, and average probability.

Lead Conversion and Opportunities

When a lead is converted to a customer via CRMLeadConvert.php, any open opportunities linked to that lead are automatically updated to reference the new customer code. This ensures a seamless transition from lead-based to customer-based opportunity tracking. The original lead ID is preserved on the opportunity for provenance.

Activity Management

The activity management system provides a unified log of all sales-related interactions — phone calls, emails, meetings, tasks, demos, and notes — linked to customers, leads, or opportunities. Activities can be scheduled for the future, completed, or cancelled.

CRM Activities (CRMActivities.php)

Lists all CRM activities with session-persistent filters:

  • Type — Filter by activity type (call, email, meeting, etc.)
  • Assigned To — Filter by the responsible salesperson
  • Status — Planned, Completed, Cancelled, or All
  • Date From / Date To — Filter by scheduled date range
  • Keywords — Search by subject or linked entity name

Each activity links to its edit page.

Activity Entry (CRMActivityEntry.php)

Create or edit a CRM activity. Fields include:

  • Activity Type — Selected from the activity types reference table
  • Subject — Brief description of the interaction (required)
  • Description — Detailed notes about the activity
  • Customer / Contact / Lead / Opportunity — Link to one or more entities
  • Assigned To — Salesperson responsible (defaults to current user)
  • Scheduled Start / End — When the activity is planned
  • Duration — Auto-calculated from start and end, or entered manually
  • Status — Planned, Completed, or Cancelled
  • Outcome / Outcome Details — Result of the activity
  • Follow-up Date — Date for a follow-up action

The entry form can be pre-populated by passing GET parameters: ?DebtorNo=X, ?LeadId=X, ?OppId=X, or ?ScheduledDate=YYYY-MM-DD (used by the calendar).

When the status changes to Completed, the completion timestamp is recorded automatically. If an already-completed activity is edited, the original completion time is preserved.

CRM Calendar (CRMCalendar.php)

A monthly calendar view showing scheduled activities. Features:

  • Navigate between months using Previous / Next links
  • Today's date is highlighted with a yellow background
  • Each activity subject is shown as a link to its edit page
  • A + link on each day creates a new activity pre-filled with that date
  • Completed activities are shown with strikethrough text
  • Salespeople see only their own activities; managers see all

My Activities (CRMMyActivities.php)

A personal dashboard for the logged-in salesperson showing three sections:

Overdue
Planned activities whose scheduled date has passed. Highlighted in red to draw attention. Each has a Complete button and an Edit link.
Today
Activities scheduled for the current day, showing the time portion. Each has a Complete button and an Edit link.
Upcoming (Next 7 Days)
Activities scheduled within the next week. Provides advance visibility of the upcoming workload.

The Complete button uses a POST form to mark the activity as completed and record the completion timestamp. Only planned activities can be completed.
